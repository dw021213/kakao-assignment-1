# 1차 → React 마이그레이션 기획서

> 코드를 바로 짜기 전에, 1차 과제(`app.js`)의 기능을 먼저 정리하고
> React에서의 구조를 정한 다음 AI에게 검토를 받고 구현을 맡기기 위해 쓴 문서예요.

## 1. 1차 과제 기능 목록 (옮길 대상)

- Todo 추가 (빈 입력 시 안내 메시지)
- Todo 완료 토글 / 삭제
- Todo 수정 → **1차에서는 `prompt()` 팝업, React에서는 인라인 입력창으로 바꿀 것**
- 상태별 필터 (전체 / 진행 중 / 완료)
- 일간 뷰 (선택한 날짜의 할 일만, 이전/다음 날짜)
- 주간 뷰 (월~일 한 줄, 날짜별 개수, 오늘/선택 강조, 이전/다음 주)
- localStorage 저장·복원 (새로고침 후 유지)

## 2. 컴포넌트 구조

```
App                      // 상태를 모두 들고 props로 내려줌 (명세 요구사항)
├─ WeekStrip             // 주간 뷰
├─ DayNavigator          // 일간 이전/다음 + 선택 날짜 라벨
├─ TodoInput             // 입력창 + 추가
├─ FilterTabs            // 전체/진행중/완료
└─ TodoList              // 목록 (빈 상태 처리)
   └─ TodoItem           // 한 항목 (완료/인라인 수정/삭제)
```

- `useTodos` 같은 커스텀 훅은 **만들지 않기로** 결정. 명세가 "상태는 App에서 관리"라고 했고,
  지금 규모에서 훅으로 빼는 건 과하다고 판단함. (규모가 커지면 재검토)

## 3. 상태 설계 (App)

| 상태 | 타입 | 저장? | 비고 |
| --- | --- | --- | --- |
| `tasks` | `{id, title, done, date}[]` | O | 1차의 네이밍(`title`/`done`) 유지 |
| `weekOffset` | `number` | O | 한 주 기준. **Date 객체 대신 숫자로** (참조 변경 이슈 회피) |
| `selectedDate` | `"YYYY-MM-DD"` | X | 새로고침 시 항상 오늘로 |
| `activeFilter` | `"all"\|"active"\|"done"` | X | |

- 저장은 `tasks`/`weekOffset` 변경 시 `useEffect` 하나로 자동 저장.
- 초기값은 함수형 초기화 `useState(() => ...)`로 한 번만 읽기.

## 4. 날짜 유틸 (`utils/date.js`)

- `toKey` / `fromKey` : 로컬 기준 `YYYY-MM-DD` 변환 (UTC 밀림 방지, 1차에서 가져옴)
- `getMonday` : 월요일 시작
- `getWeekDates(weekOffset, baseDate)` : 한 주 7일
- `getWeekOffsetOf(key, baseDate)` : 특정 날짜가 몇 주 떨어졌는지 (일간 이동 시 주간 뷰 동기화용)

## 5. 미리 적어둔 엣지 케이스 (AI 검토 후 보강)

- 한글 입력 후 엔터 → 글자 중복 (1차에서 겪음). **React에서도 막아야 함.**
- localStorage 값이 깨졌을 때 → 앱이 죽지 않고 빈 상태로 시작.
- localStorage 데이터가 기대한 모양이 아닐 때 → 모양 검사로 걸러내기.
- 빈 값으로 수정 확인 → 원래 내용 유지.
- 다른 주를 보다가 새로고침 → 주간 뷰는 유지(`weekOffset` 저장).

## 6. 진행 순서

1. 이 기획서를 AI에게 검토 요청 (빠진 기능·논리 오류 확인)
2. 기획서 기반으로 컴포넌트별 구현 요청
3. 직접 실행하며 버그 발굴 → 수정
4. 리팩토링 포인트를 AI와 토론 후 반영 여부 결정
